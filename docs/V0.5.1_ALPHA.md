# AI 酒馆 v0.5.1 Alpha 功能与验收基线

## 版本定位

- 项目名称继续使用「AI 酒馆」。
- 版本号为 `v0.5.1-alpha`，界面名称为 `v0.5.1 Alpha`。
- 本版是存储迁移与管理体验验证版，不代表正式稳定版。
- `/酒馆`、`jg` 兼容入口、包名 `astrbot_plugin_tavern` 和插件数据根目录不变。
- 0.5.0 Beta 的多人跑团、投骰、NPC、记忆、时钟、生命周期和永久归档规则全部保留。

## 存储目标

最终规则：

> 一群一目录、一轮副本实例一目录、一副本一运行库；所有独立恢复文件携带十四位数字时间。

目录示例：

```text
astrbot_plugin_tavern/
├─ catalog.sqlite3
├─ groups/
│  └─ qq_official_g_7fd89a4030a1d9bc/
│     ├─ group.json
│     └─ stories/
│        ├─ border-tavern_20260701193025_i-a82f7c3d/
│        │  ├─ manifest.json
│        │  ├─ instance.sqlite3
│        │  ├─ saves/
│        │  │  └─ save_border-tavern_20260701210030.zip
│        │  └─ backups/
│        │     └─ backup_border-tavern_20260701224518.zip
│        └─ border-tavern-run-20260702140508_20260702140508_i-b91d2e6a/
│           ├─ manifest.json
│           ├─ instance.sqlite3
│           ├─ saves/
│           └─ backups/
├─ exports/
└─ migration_backups/
```

### 稳定命名

- 群目录使用平台安全名和 `platform_id + group_id` 的稳定哈希。
- 群备注和中文群名不进入目录名，改备注不会搬动数据。
- 副本目录使用安全故事标识、创建时间和副本 ID。
- 创建时间固定为 `YYYYMMDDHHMMSS`，之后不随更新变化。
- 同一故事重新开局会生成新 session ID、新副本标识和新目录。
- 中途暂停、关闭或继续仍使用原目录。
- 克隆分支生成新目录，并在清单中记录来源副本和来源存档。

### 文件职责

| 文件 | 职责 |
|---|---|
| `catalog.sqlite3` | 全局世界、兼容事务、群目录索引、检索索引和同步状态 |
| `group.json` | 群 ID、平台、群备注、修订号和副本数量 |
| `manifest.json` | 副本身份、世界快照、创建时间、第几次游玩、分支来源、记录数和校验值 |
| `instance.sqlite3` | 仅包含当前副本及其使用版本的自包含运行库 |
| `saves/*.zip` | 手动命名存档和最终存档 |
| `backups/*.zip` | 周期安全备份和迁移备份 |

`instance.sqlite3` 使用 SQLite 原生 backup API 从一致事务视图生成，再裁剪其他副本并执行：

- `PRAGMA quick_check`
- `PRAGMA foreign_key_check`
- 单一 session ID 校验
- SHA-256 校验

任一校验失败时，不替换上一次有效副本文件；目录索引标记为 `error`，下次启动自动重试。

## 两层存档

### 回合级即时存档

以下记录继续保存在 `instance.sqlite3` 内部：

- 每回合提交前的 `undo` 回滚点
- 默认每 5 回合一次的 `auto` 检查点
- 读档等高风险操作前的 `safety` 保护点
- 管理台和群命令创建的命名快照记录

它们用于快速切换状态，不会每回合生成一个 ZIP。

### 独立安全文件

- 手动命名存档：`save_<故事标识>_YYYYMMDDHHMMSS.zip`
- 最终存档：`save_<故事标识>_YYYYMMDDHHMMSS.zip`
- 周期安全备份：`backup_<故事标识>_YYYYMMDDHHMMSS.zip`
- 同一秒重名：追加 `_02`、`_03`
- 每个副本最多轮换保留最近 20 份周期备份；手动／最终存档不参与该轮换

每个 ZIP 固定包含：

```text
instance.sqlite3
manifest.json
group_snapshot.json
checksum.sha256
```

## 旧库迁移

从 `tavern.sqlite3` 升级时：

1. 对旧库执行完整性检查。
2. 生成 `migration_backups/backup_catalog_YYYYMMDDHHMMSS.sqlite3`。
3. 使用 SQLite backup API 建立临时 `catalog.sqlite3`。
4. 增量升级到 Schema 5。
5. 为所有旧群和副本建立目录、清单和独立数据库。
6. 逐一执行快速检查、外键检查、记录范围和校验值检查。
7. 为迁移副本生成时间戳安全备份。
8. 全部成功后，旧 `tavern.sqlite3` 转存为 `backup_legacy_tavern_YYYYMMDDHHMMSS.sqlite3`。
9. 任一步失败则停止切换；原旧库不被修改。

旧数据库中的回合快照、角色、NPC、记忆、投票、计时、骰点、操作回执和永久归档全部随所属副本进入独立数据库。

## 群备注

- 唯一身份仍为 `platform_id + group_id`。
- 备注最长 120 字。
- 修改时携带 revision；其他管理员已更新时返回冲突，不静默覆盖。
- 修改行为写入审计日志。
- 保存后同步更新 `group.json`。
- 备注只用于显示和检索，不影响目录、白名单或平台路由。

## 群／故事副本检索

管理台“群会话”页提供：

```text
搜索：[群备注、群 ID、副本名称或标识…]
范围：[全部｜仅群｜仅故事副本]
分页：[上一页｜当前页｜下一页]
```

匹配范围：

| 范围 | 字段 |
|---|---|
| 群 | 群备注、群 ID、平台 ID |
| 故事副本 | 副本名称、标识、会话 ID、世界名称、世界标识 |
| 全部 | 同时匹配以上字段 |

过滤和分页在服务端完成。页面按群分组展示，群标题优先显示备注，并保留真实群 ID；副本卡片显示第几次游玩、创建时间和文件同步状态。

## 独立角色卡模板入口

入口：

```text
酒馆控制台 → 世界与角色 → 世界卡片 → 角色卡模板
```

功能：

- 导入本地 JSON，最大 1 MiB
- 导出当前 JSON
- 编辑模板
- 校验版本、字段 key、必需字段和属性预算
- 预览玩家建卡字段、私密字段与属性范围
- 恢复默认模板
- 通过校验并确认保存后才更新世界

“安全与设置 → 导入备份”仍只用于完整酒馆备份，不再与角色卡模板混淆。

## 完整备份

管理台导出：

```text
backup_tavern_YYYYMMDDHHMMSS.zip
```

内容包括：

- 一致性 `catalog.sqlite3`
- `groups/` 下的群清单、副本清单、运行库和独立存档
- 兼容的 `bundle.json`
- `checksum.sha256`

导入同时接受：

- v0.5.1 Alpha ZIP
- Schema 1—4 旧版 JSON

导入 ZIP 会先核对全部 SHA-256，并拒绝路径穿越、符号链接、重复成员和异常解压体积。活动数据库与清单由 `bundle.json` 重建，原 ZIP 中 `saves/`、`backups/` 的独立恢复文件也会还原；备份内声明的物理路径不会被信任，而是根据群与副本身份重新计算。安全合并继续采用插入式合并；覆盖恢复会替换目录库数据。来自更新 Schema 的备份仍会被拒绝。

## 验收重点

1. 两个群必须进入两个不同的稳定群目录。
2. 同一群两个副本必须进入两个不同的副本目录。
3. 同一故事完结后重新开局，必须生成新 session ID 和新目录，旧目录不变化。
4. 每个 `instance.sqlite3` 只能包含一个 session ID。
5. 副本库必须通过快速检查、外键检查和 SHA-256 校验。
6. 每回合快速恢复点留在副本库内部；不能每回合制造 ZIP。
7. 手动、最终和周期备份文件名必须含十四位数字时间。
8. 群备注修改后，管理台检索和 `group.json` 必须一致。
9. 检索范围与分页必须由后端处理，浏览器不遍历所有副本数据库。
10. 角色卡模板导入必须校验；未确认保存前不能修改世界。
11. 旧 `tavern.sqlite3` 只有在全部副本物化成功后才能转存。
12. 0.5.0 的骰点幂等、永久归档、NPC、记忆、时钟和回合流程不得回退。
