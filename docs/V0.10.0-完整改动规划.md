# AI 酒馆 v0.10.0 完整改动规划与验收清单

## 版本目标

v0.10.0 将三条原本分散的需求合并成同一条可审计、可存档、可扩展的产品链：建卡码过期自动补发；真人 DM 接管、连续推进和交棒；世界协议 v4 的通用角色预设与世界包知识/内容边界。

基线与接口版本：插件 `0.10.0`，数据库 Schema `9`，世界协议 `v4`（兼容读取 v2/v3），角色卡模板 `v5`，通用模板包 `2.0.0`，NPC 导入模板 `v1`。

## 一、建卡码过期自动补发

### 行为

1. 玩家私聊提交已过期但仍能定位到未完成席位的建卡码时，旧码原子标记为过期，系统创建新码并返回新的有效期。
2. 玩家回群重复发送 `/酒馆 加入` 时，如果席位仍保留、角色卡未完成且没有有效码，同样自动补发。
3. 新码继续绑定原参与者、席位和未完成草稿，不清空已经填写的字段。
4. 每次补发重建建卡超时计时器，并记录 `card.code_reissued` 审计；旧码不能再次消费。
5. 已批准、已归档或已释放席位不补发，避免借旧码占用新角色身份。

### 验收

- 私聊过期码能收到明确的“已自动补发”提示、新码和有效期。
- 群内重复加入能收到相同的新码，不会出现“已加入但没有码”的死路。
- 并发重复消息最多生成一个活动码；原草稿字段、预设快照和席位不丢失。

## 二、真人 DM 主持状态机

### 命令

```text
/酒馆 主持 开启 [用户ID]
/酒馆 主持 状态
/酒馆 主持 指引 <一次性导演指令>
/酒馆 主持 推进 <剧情方向>
/酒馆 主持 直述 <原文剧情>
/酒馆 主持 交棒 <玩家角色或 NPC:名称>
/酒馆 主持 自动 <玩家角色>
/酒馆 主持 接管
```

活动 DM 在主持等待态直接发送 `jg <方向>`，等价于“主持推进”；普通玩家输入被拒绝且不写入时间线。

### 状态

| 模式/阶段 | 含义 |
|---|---|
| `auto` | AI 自动玩家轮转 |
| `dm / awaiting_dm` | 等待活动 DM 连续推进或交棒 |
| `dm / generating` | 主持剧情生成中；会话锁阻止并发切换 |
| `dm / player_handoff` | 指定玩家获得一次完整行动机会 |
| `dm / npc_handoff` | 指定 NPC 演出一段，不进入玩家队列 |

### 权威提交链

`commit_dm_beat()` 在一个事务中创建撤销点、写正式叙事事件、应用世界状态补丁、NPC 操作、记忆、剧情账本、场景时钟和角色状态，并写操作审计。它可以增加叙事 `turn_no` 和主持段号，但必须恢复原玩家回合状态，因此不增加多人 `round_no`、不移动当前玩家、不创建玩家选项或倒计时。

### 冲突与安全

- 开启时旧选项以 `superseded_by_dm` 语义失效，旧行动计时器停止，但不删除历史数据。
- 未结束集体投票默认拒绝切换；暂停、安全暂停、关闭、维护和完结状态不得主持推进。
- 一个副本同一时间只有一个 `active_dm_user_id`；指定其他 DM 和强制接管只允许插件管理员。
- 一次性指引成功用于下一次 AI 推进后自动清空；原文直述不会自动修改机械事实。
- DM 指令低于插件安全规则、世界硬规则、内容边界、已锁定骰点和已发生事实，不能替玩家声明思想、感情、立场或主动台词。

### 交棒

- 玩家交棒：指定玩家成为当前行动者，得到一套基于当前场景的完整行动机会；完成后取消自动生成的后续流程并回到 `awaiting_dm`。
- NPC 交棒：读取 NPC 的公开资料、知识、误解、状态和私密导演信息，生成一段行动；不创建 A—D，不把 NPC 放入玩家队列。
- 恢复自动：必须指定玩家角色，明确下一行动者后退出 DM 模式，并清除未消费指引。

## 三、世界协议 v4 与通用预设

### 核心结构

```text
preset_dimensions
knowledge_profiles
content_profiles
knowledge_boundary
content_boundary
```

`preset_dimensions` 是通用接口，不再硬编码性别、性格、种族、职业、出身、身份、门派、阵营或信仰。维度可声明单选、多选、有序多选、条件显示、系统分配或作者固定；选项可携带数值/技能效果、行为倾向、提示片段、知识档案、内容档案、前置条件、互斥关系、初始资源和剧情钩子。

### 知识边界

最终知识由世界硬上限、所选预设知识档案和剧情中实际获得的知识共同组成。熟悉度使用固定枚举：`unknown`、`rumor`、`basic`、`familiar`、`expert`、`insider`。冲突采用保守优先级：世界禁止项 > 明确未知 > 明确已知 > 通用常识 > 模型推断。

### 内容边界

`content_boundary` 定义世界分级、绝对禁止、淡出处理、有限允许和叙事规则。预设内容档案只能新增禁止、淡出和叙事约束，不能放宽世界硬边界。玩家可由世界包决定是否进一步收紧，但不能放宽；DM 模式同样不能绕过。

### 建卡变化

- 世界协议 v4 的建卡向导自动插入并排序预设维度。
- 单选与多选都保存稳定 ID、显示值和完整选项快照；修改上游选择后按规则清理冲突与派生结果。
- 玩家不再填写“知识边界”和“个人内容边界”；确认角色卡时解析结构化最终边界，并在预览中显示来源。
- 世界协议 v2/v3 继续使用旧建卡行为；运行中副本始终读取创建时冻结的世界快照。

## 四、公开接口与事件

### 主持服务

```python
get_control_state(session_id)
enable_dm_mode(session_id, dm_user_id, actor_id)
set_dm_directive(session_id, directive, actor_id)
generate_dm_beat(event, session_id, instruction, actor_id)
append_dm_narrative(session_id, narrative, actor_id)
handoff_to_actor(session_id, actor_type, actor_ref, actor_id)
return_to_auto(session_id, participant_ref, actor_id)
takeover_dm(session_id, new_dm_user_id, actor_id)
```

### 预设与边界服务

```python
list_preset_dimensions(world)
resolve_character_presets(world, selections)
explain_boundary_sources(world, selections)
check_character_knowledge(resolved, domain)
check_content_permission(resolved, content_tags)
```

事件覆盖 DM 启停、分配、指引、推进、直述、交棒和接管，以及预设选择、边界解析与边界阻止。扩展只能观察已提交事件，不能取得数据库连接或绕过领域服务。

## 五、WebUI

会话详情显示“AI 自动 / DM 主持”、活动 DM、当前阶段、连续段号和一次性指引状态。管理员可开启/接管、保存指引、原文插入和恢复自动；AI 辅助推进及玩家/NPC 交棒继续使用群命令并与同一数据库、锁、快照和审计链联动。世界编辑/导入链完整保留协议 v4 新字段和未知安全扩展字段。

## 六、《潮痕无字》v2.0.0

- 升级到世界协议 v4、角色卡模板 v5，最低插件版本 0.10.0。
- 新增性别、性格，并将地区、身份、门派、主/辅修流派、奇术和两项百业全部声明为通用预设维度。
- 性别只影响称谓与代词；六类性格只影响表达与倾向，不替玩家作决定。
- 63 个可复用知识档案覆盖所有世界预设；每个选项均有知识档案和内容档案引用。
- 删除玩家填写知识/内容边界的步骤；世界级硬边界和预设级附加边界写入包内。
- 原 `preset_stack` 五维公式保持不变：基础 25 + 地区 2 + 身份 1 + 主修 3 = 总和 31。
