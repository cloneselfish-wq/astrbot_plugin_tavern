# AI 酒馆 v0.5 Beta 功能与验收基线

## 版本定位

- 项目名称继续使用「AI 酒馆」。
- 对外定位：AI 主持的多人群聊跑团与互动叙事插件。
- `/酒馆`、内部包名 `astrbot_plugin_tavern`、配置文件名和存档目录均不改名。
- 本版仍是内部测试版，不代表 `v1.0.0` 正式版。

## 本版目标

0.5 Beta 把已有的多人席位、私聊建卡、四选一、轮次、投票、世界事件、长期记忆和存档流程，扩展为一套由插件进行权威裁定、由模型负责叙事的轻规则多人跑团系统。

核心边界：

1. 插件锁定选项、属性、DC、风险、优劣势来源、骰点和最终状态变更。
2. 模型只能根据锁定结果叙事和提出受限状态操作。
3. 重试、备用模型切换和 Bot 重载不得重新投骰。
4. 玩家角色的思想、感情和未选择对白不由 AI 决定。
5. 普通群聊继续完全旁路，不消耗酒馆模型或污染剧情数据。

## 检定规则

| 项目 | 默认规则 |
|---|---|
| 常规检定 | `1D20` |
| 优势 | `2D20` 取高 |
| 劣势 | `2D20` 取低 |
| 同类叠加 | 不继续增加骰子，但保留全部来源 |
| 优劣同时存在 | 相互抵消，恢复常规投骰 |
| 结果 | 大成功、成功、代价成功、失败、大失败 |
| 自然 20 | 大成功，但不能突破世界事实 |
| 自然 1 | 大失败，但不单独造成死亡 |
| 致命风险 | 必须提前明示已知后果 |
| 测试期可见性 | 完全公开 |

默认总值：

```text
检定总值 = 保留的 D20 + 已审核角色属性加值 + 明确的特殊修正
```

DC、风险和态势修正分工如下：

- 角色属性提供稳定加值。
- 专长、装备、协助、伤势和环境通常提供优势或劣势。
- 行动本身的难度决定 DC。
- 失败有多严重由风险等级决定。
- 同一个原因不能既提高 DC，又造成劣势。

### DC 档位

| DC | 难度 |
|---:|---|
| 5 | 极易 |
| 8 | 容易 |
| 10 | 普通 |
| 12 | 标准 |
| 15 | 困难 |
| 18 | 非常困难 |
| 20 | 极限 |
| 25 | 传奇 |

### 风险等级

| 风险 | 典型失败后果 |
|---|---|
| `safe` | 无进展或少量时间流逝 |
| `controlled` | 暴露痕迹、消耗工具、轻微状态 |
| `dangerous` | 受伤、失去资源、推进威胁时钟 |
| `desperate` | 严重伤势、分离、被俘、关键资源丢失 |
| `lethal` | 可能死亡或永久改变角色，必须预先明示 |

无风险且无不确定性的行为直接成功；明确不可能的行为直接拒绝。失败必须继续推动局势，关键主线线索不能因一次失败永久消失。

## 多人协作与角色资源

### 协助

- 协助者用自己的行动说明目标、方式和适用检定。
- 必须具备相关能力、工具或合理位置。
- 成功后建立一次性协助标记。
- 同一次检定最多消费一个协助标记。
- 标记使用后或本轮结束时失效。
- 协助有风险时，后果可以合理波及协助者。

### 灵感

- 每名角色初始 1 点，上限 3 点。
- 每次检定最多使用 1 点。
- AI 不得替玩家擅自消费。
- `/酒馆 灵感 A`：投骰前取得优势或抵消劣势。
- `/酒馆 灵感重投 A`：预授权重投整个骰池，必须接受新结果。
- 获得和消费均写入持久流水。

### 伤势与状态

- 只保存在副本运行层，不覆盖角色基础卡。
- 每项状态保存名称、严重程度、影响范围、效果、解除条件和来源事件。
- 状态只影响相关行动，不对所有检定无差别施加劣势。
- 体力归零通常是失去行动能力，不自动死亡。

### 多人检定类型

- 领队检定：一人主导，其他角色提供协助。
- 集体检定：参与者分别投骰，超过半数成功则团队成功。
- 独立抵抗：每名受影响角色分别检定并结算。
- 对抗检定：双方主动投骰比较，平局默认防守方胜。
- 投票只决定团队是否执行，不替代后续检定。

## 场景、任务与信息

### 场景时钟

- 支持 4、6、8 格。
- 可设为公开、模糊或隐藏。
- 失败、代价成功、拖延、世界脉冲和 NPC 场外行动可推进时钟。
- 填满后只触发一次对应事件，并锁定完成状态。

### 剧情账本与进度

- 保存主目标、支线、线索、章节、已完成里程碑和失败目标。
- 只有存在正式 `completed_milestones / total_milestones` 时才显示进度百分比。
- 没有正式里程碑时，只展示章节、当前目标和最近场景摘要。

### 信息边界

信息至少分为：

- 全队公开
- 单个玩家私有
- NPC 已知
- 主持人或世界真相

NPC 的陈述、谣言和误解不能自动升级为世界事实。只有与当前地点或近期剧情相关的 NPC、记忆和账本条目进入模型上下文；锁定事实不受普通裁剪影响。

## 副本 NPC

- 世界常驻 NPC 在创建副本时复制为副本角色。
- 模型生成的 NPC 只属于当前副本，不回写世界模板。
- 自动登记必须有名字，并至少满足直接互动、掌握重要线索或进入长期记忆之一。
- 单回合最多自动新增 3 名。
- 自动 NPC 默认待管理员复核，但可立即参与当前剧情。
- 同名或别名冲突保存为疑似重复提案，不静默合并。
- 模型只能填写公开资料、认知和运行状态，不能写系统级私密提示词。

## 记忆治理

长期记忆并入群会话详情，不再作为独立导航入口。每条记忆可设置：

- 锁定与置顶
- 全队、主持人或个人可见
- 来源事件
- 已失效
- 被新事实替代
- 冲突待确认

锁定和置顶事实优先进入上下文；无效或被替代的事实保留审计，但不再作为当前事实使用。

## 玩家安全与内容边界

- 世界模板和副本都可设置角色死亡、玩家冲突、恋爱、恐怖程度和成人内容边界。
- 玩家互害、偷窃、控制等内容必须遵循目标玩家同意规则。
- 任何活跃玩家都可发送 `/酒馆 安全暂停`。
- 安全暂停不要求玩家公开原因，并冻结行动、投票和其他活动计时。
- AI 只描述外部刺激、玩家已选行动的结果、NPC 与世界反应。

## 时间规则

界面统一使用“数值＋单位＋不限时”。空白或 `-1` 保存为 `null`，`0` 非法；`max_consecutive_timeouts = -1` 表示永不自动转候补。

| 项目 | 默认值 | 到期处理 |
|---|---:|---|
| 私聊建卡码 | 30 分钟 | 失效，可重新申请 |
| 角色卡草稿 | 7 天 | 标记过期，不删除 |
| 完成角色卡 | 24 小时 | 释放本次席位，保留草稿 |
| 准备大厅 | 24 小时 | 只提醒主持人，不自动开演 |
| 玩家准备确认 | 30 分钟 | 转入候补 |
| 个人行动回合 | 10 分钟 | 跳过并累计一次超时 |
| 回合提醒 | 剩余 3 分钟 | 提醒当前玩家 |
| 连续超时 | 2 次 | 转入候补 |
| 候补自动退场 | 7 天 | 安全退场并释放席位 |
| 代控授权 | 24 小时 | 自动撤销 |
| 检定或补充选择 | 5 分钟 | 采用保守结果或取消 |
| 第一轮投票 | 10 分钟 | 无多数则进入决选 |
| 第二轮投票 | 5 分钟 | 平票维持现状 |
| 投票提醒 | 剩余 2 分钟 | 提醒未投票玩家 |
| 全员无互动 | 10 分钟 | 自动暂停副本及全部计时 |

管理台提供即时团、慢速群团和全手动推进三套预设。模型请求、数据库锁等技术超时不能设置为不限时。

## 生命周期

| 操作 | 语义 |
|---|---|
| 关闭 | 软关闭，之后可以重新进入准备状态 |
| 完结 | 正常结局，建立最终存档并永久归档 |
| 强制终止 | 异常结束，记录原因并永久归档 |
| 克隆 | 从当前状态、指定存档或最终存档创建新副本 |

完结与强制终止会在一个事务中建立最终保护存档、取消选项/投票/计时、撤销代控和临时权限、解除群绑定、记录操作者/类型/原因，并把原副本改为只读。

归档副本不能直接复活。续作或分支必须克隆为新副本。

## 管理台变化

- 群会话改为卡片，并显示章节、目标、正式进度、阵容、行动者、等待流程、NPC、记忆、存档和恢复状态。
- 长期记忆并入副本详情。
- 世界编辑器新增独立的玩家角色卡模板 JSON、结构校验、默认恢复、建卡预览和模板版本。
- 副本详情新增规则、阵容、NPC、记忆、剧情账本/时钟、时间、工作流、权限、存档和时间线分页。
- 原生插件配置新增 4 个标准备用供应商选择器。
- 酒馆控制台保存配置后回读校验，并显示配置修订号、保存时间和模型链健康。
- 归档卡片只允许查看、导出和克隆。

## 数据与兼容

- 数据库版本：Schema 4。
- v0.1—v0.4 数据原位增量迁移，不要求清空存档。
- 旧检定按常规单骰、无优劣势来源解释，不重写历史结果。
- 旧 `finished` 副本迁移为永久只读归档。
- 迁移前自动生成一致 SQLite 备份；备份失败则停止升级。
- Schema 1—3 JSON 可导入 0.5；Schema 4 备份包含全部新增表。

主数据库位置：

```text
AstrBot/data/plugin_data/astrbot_plugin_tavern/tavern.sqlite3
```

迁移备份位置：

```text
AstrBot/data/plugin_data/astrbot_plugin_tavern/migration_backups/
tavern-before-schema-4-<UTC时间>.sqlite3
```

## 内测验收重点

1. 同一检定在主模型失败、备用模型接管和 Bot 重载后始终复用同一骰池。
2. 优劣势来源必须来自已审核角色卡、运行状态、协助或持久化场景事实。
3. 灵感、协助、伤势、NPC、记忆、时钟与账本同回合原子提交。
4. 集体投票不会消耗当前行动，并在结束后恢复同一行动者。
5. 自动 NPC 不污染世界模板，重复名字不会静默创建可信副本。
6. 无正式里程碑时不显示伪造的剧情百分比。
7. 安全暂停冻结全部活动计时，恢复后剩余时长正确。
8. 完结和强制终止后所有写入口均拒绝，克隆后的新副本可正常准备。
9. 原生设置页与酒馆控制台保存后读取到同一配置。
10. 旧数据库迁移前生成备份，旧存档、角色、记忆、投票和计时数据保留。
