# v0.6.0 功能与验收基线

## 版本与兼容

- 插件版本：`v0.6.0`
- 数据库 Schema：`6`
- 支持 v0.1—v0.5.3 Alpha.1 数据与存档原地升级。
- 安装时不得删除 `data/plugin_data/astrbot_plugin_tavern/`。
- 保留 Windows SQLite 文件锁保护、QQ 官方群真实艾特、建卡私聊提醒和群内建卡完成通知。

## 剧情恢复

- 新副本只使用 `/酒馆 开演`；已经产生剧情且完成恢复准备的副本只使用 `/酒馆 继续`。
- 暂停、读档和回滚后先使用 `/酒馆 恢复` 进入恢复准备大厅；全员准备完成后才提示 `/酒馆 继续`。
- `/酒馆 恢复` 只切换到恢复准备大厅，不恢复剧情或计时；`/酒馆 继续` 在暂停状态下只提示正确指令，不再自动切换状态。
- 正式继续时原样重放存档点最后一段正式剧情、当前行动者、活动选项或集体投票。
- 恢复旧选项不调用模型，不执行 100—300 字／50 字的新生成规则校验。
- 准备大厅计时器在继续时关闭；暂停的行动或投票倒计时按保存的剩余时间续跑。
- 命名存档的事件锚点继续限制模型历史；被放弃的后续分支可审计但不进入新叙事上下文。

## 叙事与选项容错

- 故事核心、世界状态、记忆和检定与下一回合选项分层校验。
- 合格故事不会因 A/B/C/D 局部错误被重新生成。
- 无歧义的标签差异可机械规范化；真正缺项、重复、超长、无安全项或角色越权会进入选项专用修复。
- 选项修复只返回四个选择，不得重写故事、状态、骰点或记忆。
- 全部模型失败时使用插件安全兜底选项，并绑定权威下一位参与者 ID。
- 集体投票不需要个人选项；检定结果一旦写入操作回执，任何选项修复都不得重新投骰。

## 回合输出

- 有效选择提交后立即主动发送“正在生成中”。
- 故事正文与“回合秩序＋下一位选项”分开发送。
- 故事正文保持 100—300 个可见字符，段落之间插入 `-----------`。
- 新生成的每个行动选项不超过 50 字，并保持至少一个安全选项。
- 其他玩家只向模型暴露当前可观察信息；选项不得替其他玩家角色作决定。

## 管理与存储

- 倒计时总开关和七类独立开关位于副本“时间与流程”。
- 群 Token 限额位于群会话标题入口；副本详情只管理当前副本限额。
- 群／副本 Token 流水在调用前事务预占，完成后按供应商实报或本地估算结算。
- 支持强制全员准备、同名存档覆盖确认、快速存档删除、独立存档回收和整个已关闭／已归档副本删除。
- 玩家主动放弃行动使用 `/酒馆 跳过`；管理员强制推进使用 `/酒馆 强制下一位`，避免与普通续演混淆。
- 私聊角色卡提醒统一使用 `/酒馆 建卡提醒`；副本倒计时策略统一使用 `/酒馆 倒计时`。
- 永久归档保持只读；Schema 6 完整 ZIP 和旧版备份继续按安全校验规则导入。

## 发布验证

```bash
python -m unittest discover -s tests -v
python -m py_compile main.py tavern/*.py
node --check pages/console/app.js
python -m json.tool _conf_schema.json
```

正式 ZIP 必须通过 CRC 检查，并在全新解压目录中再次执行同一套测试。
