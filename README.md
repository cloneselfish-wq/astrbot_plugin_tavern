# AI 酒馆

> 📣 **项目交流群：QQ 群 `1094220887`**  
> 欢迎交流世界包制作、插件测试、问题反馈与版本更新；入群时请说明来自 AI 酒馆项目。

> 当前版本：`v0.11.2`  
> 作者：`Ghostberry`  
> 数据库版本：Schema 10  
> 世界包协议：v2 / v3 / v4 / v5  
> 角色卡模板：v6  
> 通用模板包：v3.0.0

AI 酒馆是一个面向 AstrBot 群聊环境的多人跑团与互动叙事插件。它将“主持、建卡、审核、行动回合、机器检定、集体投票、剧情推进、状态持久化、暂停恢复和后台管理”组合为一套完整流程，适合在 QQ 群等多人会话中长期运行故事副本。

插件不是普通的自由聊天机器人。只有明确的酒馆指令和剧情触发内容会进入系统；普通群聊始终旁路，不调用酒馆叙事模型，也不会写入酒馆时间线。

## 一、主要能力总览

### 1. 多群、多世界、多副本

- 不同群的故事、角色、存档、NPC、Token 用量和时间线相互隔离。
- 同一群可以保存多条不同副本，每条副本都有独立标识和独立数据。
- `/酒馆 开启` 会列出当前群已有副本；若本群还没有副本，则列出可创建副本的世界包。
- 列表每页最多显示 5 项，包含副本或世界简介，支持翻页。
- 世界模板更新后，只影响以后新建或克隆的副本；正在运行的副本继续使用创建时冻结的世界快照。

### 2. 准备大厅与严格开演检查

- 玩家先加入副本、获得席位和建卡码。
- 玩家主动私聊机器人完成角色卡。
- 角色卡根据世界设置自动通过，或进入管理员审核。
- 审核通过的出场角色需要发送 `/酒馆 准备`。
- 开演前检查最低人数、最大人数、角色卡状态、准备状态、世界契约和骰制是否有效。
- 主持人必须显式发送 `/酒馆 开演`，插件不会在最后一人准备后自动开演。

### 3. 多人行动回合

- 维护确定的行动顺序和多人轮次。
- 每次只允许当前行动者推进剧情，防止抢话和串台。
- 当前玩家从 A、B、C、D 四个行动意图中选择。
- 可使用 `jg A` 或 `/酒馆 选择 A`；字母后可以附加简短演绎。
- 玩家声明的是“尝试”，不能自行宣布成功、伤害、物品获得或 NPC 反应。
- 当前玩家不能替其他玩家角色决定台词、情感、内心或行动结果。
- 回合结束后自动推进下一位，并显示新的回合秩序与选项。

### 4. 权威机器检定

- 是否检定、使用哪个属性、风险等级、DC 和结果档位均由结构化规则约束。
- 随机骰点由插件生成，不由文字模型编造。
- 检定结果先持久化并公开，再交给模型续写。
- 模型超时、重试、修复或恢复时复用同一检定回执，不会重复投骰。
- 内部属性使用稳定 ID，玩家可见位置使用世界包中的中文标签。
- 支持普通、优势、劣势、对消、自然 1/20、成功差值与代价成功等规则。

### 5. 集体投票

- 影响全队的重要决定可转入集体投票。
- 所有合格出场玩家可使用 `/酒馆 投票 A` 投票。
- 截止前允许改票。
- 第一轮无人过半时，可按副本规则进入前两项决选。
- 集体投票不消耗当前玩家的个人行动机会。
- 投票结束后由系统恢复或生成个人行动选项。

### 6. 私聊建卡、审核与修订

- 群内预留席位并生成绑定码，私聊完成角色卡，避免私人字段泄漏。
- 建卡码过期后，玩家私聊提交旧码或在群内再次发送 `/酒馆 加入`，系统都会自动作废旧码、补发新码并保留原草稿与席位。
- 建卡采用逐字段向导，只显示当前步骤需要的内容。
- 预设支持分页、序号、名称、稳定 ID 和别名选择。
- 支持条件字段、字段互斥、返回上一步、指定字段修改和当前步骤重显。
- 支持完整预览、取消草稿、确认提交、管理员审核与审核备注。
- 已批准角色需要修改时，会生成候选角色卡版本；审核前不会覆盖当前正式版本。
- 私密字段在群内审核详情中隐藏，但管理员可在后台查看完整内容。

### 7. 多种属性生成模式

- `none`：世界不使用角色属性。
- `manual`：玩家逐项分配，插件按预算、上下限和修正表校验。
- `preset`：选择职业基础属性，再选择主属性与副属性固定加成。
- `preset_stack`：基础值叠加地区、身份、流派等多个预设来源，插件自动生成最终属性。

### 8. 存档与恢复

- 每隔指定回合自动创建保护快照。
- 主持人可创建命名存档、覆盖同名存档、删除普通手动存档和读取存档。
- `/酒馆 回滚` 恢复最近一个自动保护点。
- 读档或回滚后会话自动暂停，必须重新进入恢复准备大厅。
- 暂停时保留最后剧情、当前行动者、A—D 选项、投票状态和计时剩余值。
- 恢复不会跳回开场，也不会重新生成暂停前选项。

### 9. 管理与安全

- 管理员、主持人、秩序管理员、普通玩家具有不同权限边界。
- 支持强制全员准备、强制下一位、调整顺序、指定行动者、让角色退场。
- 支持副本、群和全局范围封禁；封禁会原子移出队列、撤销代控并释放席位。
- 任一当前出场玩家可使用 `/酒馆 安全暂停` 立即冻结故事和全部计时，无需公开原因。
- 支持审计记录、脱敏诊断、事务恢复、精确急救、完整备份和回收目录。

### 10. 管理台与世界创作

- 可视化维护世界包、角色卡模板、常驻 NPC、群副本、玩家、记忆、场景时钟和剧情账本。
- 世界包导入前执行严格体检，并可进行试运行。
- 世界包编辑、导入、保存、导出会保留协议字段和未知扩展字段。
- 支持世界协议 v2/v3/v4/v5、角色卡模板 v5/v6 和 NPC 导入模板 v1/v2。
- 提供手动属性、`preset_stack`、能力、交互规则及 v5 综合模板，并可对规则执行 dry-run。

### 11. 真人 DM 主持与交棒

- `/酒馆 主持 开启` 可在任意正常玩家回合接管叙事，旧选项标记失效并停止旧计时器。
- `/酒馆 主持 指引` 保存一次性导演指令；`推进` 由 AI 辅助生成正式剧情；`直述` 原样写入剧情。
- 主持推进可更新世界状态、NPC、记忆、剧情账本和场景时钟，但不会移动玩家行动指针、消耗玩家回合或生成 A—D。
- `/酒馆 主持 交棒 <角色或 NPC:名称>` 可暂时交给玩家行动一次或让 NPC 演出一段；`自动 <角色>` 恢复正常 AI 自动轮转。
- 主持状态进入会话锁、自动撤销点、存档/回滚、审计、公开 API 与 WebUI；暂停态、安全暂停和未结束投票仍具有更高优先级。

### 12. 世界协议 v4 通用预设与边界

- 世界包通过 `preset_dimensions` 声明性别、性格、出身、身份、门派、职业、信仰等任意单选、多选或条件预设，插件不再为每种字段硬编码。
- 每个选项可绑定数值、提示词、知识档案、内容档案、初始资源、前置条件与互斥关系。
- `knowledge_boundary` 与 `content_boundary` 由世界包提供硬边界；角色最终边界由所选预设结构化合成，并在角色预览中展示来源。
- 玩家不再重复填写知识边界和内容边界；世界包可允许玩家进一步收紧，但预设、玩家和 DM 都不能放宽世界硬边界。

### 13. 世界协议 v5 通用规则底座

- 世界包以 `protocol.features` 只启用实际需要的模块；能力、资源、对象、持续效果、裁定方式和交互关系都不是必选项。
- Entity Registry、Condition Engine、Operation Engine、Event Pipeline 与 Resolution Receipt 共同提供类型化引用、受控读取、白名单变更、事件阶段和可回放凭证。
- `interaction_rules` 不内置火克冰、敌我、HP、骰制或任何世界观语义；世界作者可以定义数值、身份、环境、线索或纯叙事关系。
- AI 只看到当前角色可用能力的投影；插件再次校验行动、目标、限制和消耗，机械结果由幂等事务提交。

## 二、运行概念与权限

### 世界、世界模板与世界快照

“世界”是可复用的规则模板，包含世界规律、角色卡、属性、骰制、风险映射、开场、初始状态、事件池、时间规则和 NPC 策略。

新建副本时，插件会冻结当时的世界规则作为“世界快照”。之后即使管理台修改了原世界模板，旧副本也不会被静默改变。要让旧故事使用新版世界，应先体检新版世界，再从合适存档克隆新副本或新建故事。

### 副本

副本是一条具体故事线，拥有独立的：

- 群与平台绑定；
- 世界快照；
- 玩家与角色卡；
- 当前地点、时间和场景摘要；
- 剧情事件、长期记忆、任务线索与 NPC 关系；
- 当前行动顺序、选项和投票；
- 计时器、Token 流水和限额；
- 自动快照、命名存档和独立安全文件。

### 会话状态

| 状态 | 含义 |
|---|---|
| `closed` | 副本关闭，不处理剧情消息、不调用模型 |
| `preparing` | 准备大厅，可加入、建卡、审核和准备；也用于暂停后的恢复准备 |
| `running` | 故事运行中，可选择行动、检定、投票和推进剧情 |
| `paused` | 故事与计时冻结，现场完整保留 |
| `maintenance` | 维护状态，只允许管理、修复和诊断操作 |
| `finished` | 已完结或强制终止，只读归档 |

### 权限层级

| 身份 | 主要权限 |
|---|---|
| 插件管理员 | 配置中的真实管理员 ID；可管理所有群、世界、备份、全局封禁和安全设置 |
| 副本主持人 | 创建或获授权主持副本；可开演、暂停、恢复、继续、存读档和结束副本 |
| 秩序管理员 | 可处理审核、顺序、指定行动者、退场、封禁、计时等秩序操作 |
| 普通参与者 | 加入、建卡、准备、行动、投票、暂离、返场、代控授权和安全暂停 |

若开启强制群白名单，只有允许群能使用插件。首次安装后必须先配置至少一个真实管理员 ID；否则插件只会提示尚未初始化。

## 三、安装、升级与首次配置

### 安装

1. 在 AstrBot 插件管理中安装插件 ZIP；也可以把完整的 `astrbot_plugin_tavern` 目录放入 AstrBot 插件目录。
2. 重启 AstrBot，确认插件版本显示为 `0.11.2`。
3. 打开插件配置或酒馆控制台。
4. 在“管理员 ID”中填写至少一个真实用户 ID。
5. 选择主聊天模型；按需配置 1—4 个备用模型。
6. 如需让玩家以图片参与行动，单独配置图片转述模型。
7. 建议保持强制群白名单开启。
8. 由已配置管理员在目标群发送 `/酒馆 开启`。若该群尚未进入白名单，插件可识别并绑定平台实例 ID 与群 ID。

### QQ 指令前缀

插件命令解析支持以下开头：

```text
/酒馆
／酒馆
!酒馆
！酒馆
```

若 QQ 官方平台不接受半角斜杠，请直接使用全角形式 `／酒馆`。本文为便于阅读统一写作 `/酒馆`。

### 升级到 v0.11.2

- `v0.11.1` 可直接升级到 `v0.11.2`：数据库仍为 Schema 10，无需迁移。
- 修复「全队行动」选项归属与流程：选项列表将个人选项与「🌐 全队行动 · 需集体表决」分区展示；选中全队行动选项后由引擎直接发起全员投票（不再依赖模型生成 `group_decision`，不再整轮判“未提交”）。
- 修复检定骰值复用：骰值锁定键加入所选选项与检定类别（stat/check_type），不同检定独立掷骰；同选项同检定重试仍幂等返回同一骰值。
- 修复「表决通过后无后续」：`/酒馆 投票` 表决通过后立即生成并发送故事推进与新选项；投票结束作废残留旧选项，避免 WebUI 显示过期内容。
- 浏览器旧界面请强制刷新管理台页面。

### 升级到 v0.11.1

- `v0.11.0` 可直接升级到 `v0.11.1`：数据库仍为 Schema 10，无需迁移；升级前 AstrBot 仍会自动制作一致性备份。
- 修复：不限时建卡码不再被误判过期；世界包导入冲突提供“覆盖为新修订 / 另存副本 / 取消”决策弹窗；克隆副本文件同步不再因 `world_snapshots` 的 RESTRICT 外键报 `FOREIGN KEY constraint failed`；`world_simulate` 补齐登录鉴权与输入上限；回合落库与事务回执完成合并为同一事务；修复 `planning_prompt` 缺失函数体导致自由输入以空提示调用模型的问题。
- 性能：`events(created_at)` 索引、模型重试全局上限、会话锁回收、规则模拟按世界快照缓存。
- 世界协议 v5 继续要求 `minimum_plugin_version >= 0.11.0`（0.11.1 满足）；浏览器旧界面请强制刷新管理台页面。

### 升级到 v0.11.0

- `v0.10.0` 可直接升级到 `v0.11.0`；启动时先为 Schema 9 数据库制作一致性备份，再原地迁移到 Schema 10。
- 现有世界会按创建时间与内部 ID 确定性补齐永久 `display_no`；管理排序只修改独立的 `sort_order`，删除后的编号不复用。
- 运行中的旧副本继续使用冻结的 v2/v3/v4 世界快照；只有新建副本或通过兼容预检的“克隆并应用”分支使用 v5 规则。
- Schema 9 与 Schema 10 完整备份均可导入；导入旧备份时补齐稳定编号和迁移凭证。
- 升级前仍建议在控制台导出完整 ZIP 备份。
- 升级插件后重启 AstrBot，再导入要求 `minimum_plugin_version >= 0.11.0` 的 v5 世界包。
- 浏览器若仍显示旧界面，应强制刷新管理台页面，清除旧静态资源缓存。

### 不兼容边界

- `v0.8.x` 及更早数据库不能直接迁移到 `v0.9.x`。
- Schema 1—7 备份不会被 Schema 8 静默转换。
- 世界协议 v1 或未声明协议版本的世界包会被拒绝。
- 需要保留旧团时，应继续使用对应旧版插件和旧数据目录。

## 四、从开馆到开演的完整流程

### 1. 主持人选择或建立副本

```text
/酒馆 开启
```

若当前群已有副本，系统列出副本状态、标识、世界与简介。若没有副本，则列出可用世界。每页最多 5 项。

```text
/酒馆 开启 第2页
/酒馆 开启 <副本标识>
/酒馆 开启 <世界标识>
```

开启已有故事会进入准备大厅，并保留既有剧情进度。首次从世界建立副本，则进入新故事准备大厅。

### 2. 玩家加入

```text
/酒馆 加入
```

系统预留席位并生成建卡码。若玩家已经拥有该副本的角色卡，则显示当前角色卡和参与状态。

### 3. 玩家主动私聊机器人建卡

QQ 官方机器人不保证能够主动发起首次私聊，因此玩家需要先打开与机器人的私聊窗口：

```text
/酒馆 建卡 <建卡码>
```

之后按照向导逐步填写，最后使用：

```text
/酒馆 预览
/酒馆 确认建卡
```

### 4. 管理员审核

若角色卡未配置自动通过，管理员在群内使用：

```text
/酒馆 审核
/酒馆 审核 <序号或审核号>
/酒馆 审核 <序号或审核号> 通过 [备注]
/酒馆 审核 <序号或审核号> 驳回 [原因]
```

待审核列表每页最多 5 张。私密字段只显示“已填写”，不会在群内展开。

### 5. 玩家准备

```text
/酒馆 准备
```

只有角色卡审核通过且处于出场状态的玩家才能完成准备。

### 6. 主持人开演

```text
/酒馆 开演
```

插件完成所有开演前检查后，发送开场剧情、当前行动者和第一组 A—D 选项。

## 五、玩家建卡系统

### 建卡字段

角色卡字段完全由世界包定义，常见字段包括：

- 角色姓名、代号；
- 种族、职业、出身地区、社会身份、阵营、主修流派；
- 外貌、背景、当前目标、行事原则；
- 信念、牵挂、关系、专长、缺陷和现实弱点；
- 知识边界、私人秘密和个人内容边界；
- 世界自定义的条件字段和多选字段；
- 角色属性、修正值和属性来源快照。

字段可设置必填、最大长度、私密、显示条件、互斥关系和修改后清理的下游字段。

### 当前步骤填写

在私聊中，可以直接回复内容，也可以发送：

```text
/酒馆 填写 <内容>
```

系统只接受当前步骤对应的数据。无效输入不会推进步骤，也不会清空已经完成的其他字段。

### 预设选择与分页

`preset_select` 等预设字段会显示当前页选项。玩家可回复：

- 当前页序号；
- 预设稳定 ID；
- 保存值；
- 显示名称；
- 世界包配置的别名。

翻页命令：

```text
下一页
上一页
```

翻页只改变当前选项页，不会提交字段或推进建卡步骤。

### 返回与修改

```text
/酒馆 当前步骤
/酒馆 上一步
/酒馆 修改 <字段名称或稳定key>
```

- `当前步骤`：重新显示当前字段和对应预设。
- `上一步`：返回前一个当前可见字段。
- `修改`：直接跳到指定字段重新填写。
- 修改上游字段后，世界包声明的相关下游字段会被清理并要求重填。
- `visible_when` 条件变化后，不再可见的字段不会继续参与最终角色卡。

### 属性填写与重填

仅 `manual` 和 `preset` 等需要人工分配的模式使用：

```text
/酒馆 重填数值
```

该操作保留文字角色资料，只重新进入数值分配流程。

对于 `preset_stack` 世界，该命令不能直接修改派生属性。玩家应使用 `/酒馆 修改 <来源字段>` 修改地区、身份、流派等来源，系统会从基础值重新计算。

### 预览、提交与取消

```text
/酒馆 预览
/酒馆 确认建卡
/酒馆 取消建卡
```

- 预览显示全部可公开字段、最终属性和当前完成状态。
- 私密字段在私聊预览中可供本人核对；群内不会公开正文。
- 确认建卡会将草稿提交自动审批或管理员审核。
- 取消建卡会删除当前草稿并释放预留席位。

### 建卡提醒

```text
/酒馆 建卡提醒
/酒馆 建卡提醒 开
/酒馆 建卡提醒 关
```

用于在私聊中查询或切换当前角色卡的倒计时提醒。实际是否计时还取决于副本倒计时总开关和“角色卡完成”分类开关。

### 角色卡版本与二次修改

已审核通过的角色卡不会被编辑草稿直接覆盖。修改后会产生候选版本：

- 旧正式角色卡继续用于当前检定和叙事；
- 新版本进入待审核状态；
- 管理员通过后才替换正式版本；
- 驳回后保留原正式角色卡；
- `preset_stack` 来源修改会在候选版本中从基础值重算。

## 六、多人回合与剧情推进

### 行动格式

当前行动者可发送：

```text
jg A
/酒馆 选择 A
/酒馆 选择 A 我尽量压低声音，不惊动门后的人
```

默认剧情触发前缀为 `jg`，必须采用“前缀 + 空格 + 内容”。单独发送 `jg`、把 `jg` 放在句子中间或写成更长的相似单词都不会触发。

### A—D 选项

每组选项包含四个有效行动意图。选项可能同时标明：

- 是否需要检定；
- 使用的中文属性；
- 风险等级；
- 检定类型；
- 玩家在选择前应知晓的可能后果。

安全选项不得配置检定。`safe + check` 会被插件确定性规范为安全免检，不为此额外调用模型。

### 玩家自主权

插件会约束叙事模型：

- 不替玩家决定未选择的台词、情感、立场和内心；
- 不允许玩家通过输入直接宣布行动成功；
- 不允许一名玩家控制其他玩家角色；
- 不允许角色通过输入修改系统规则、管理员权限、世界包或输出协议；
- NPC 只能依据身份、经历和已知事实行动，不得无理由全知；
- 已发生的地点、时间、伤势、物品和关系必须保持连续。

### 重整选项

```text
/酒馆 重整选项
```

当前玩家可免费重整本回合选项一次。重整只替换行动选项，不撤销已经提交的故事状态，也不允许无限刷新。

### 查看顺序

```text
/酒馆 顺序
/酒馆 轮次
```

准备阶段显示阵容；运行阶段显示当前多人轮次、行动顺序、当前行动者和有效选项；投票期间同时显示投票状态。

### 跳过行动

```text
/酒馆 跳过
```

当前玩家主动放弃本次行动并推进下一位。主持人或经授权的代控者可按权限处理指定角色。

## 七、机器检定、优势、劣势与灵感

### 两阶段检定

严格两阶段模式下，流程固定为：

1. 玩家选择一个已标记检定的选项。
2. 插件从冻结世界快照读取属性、风险和规则。
3. 插件根据风险映射权威 DC。
4. 注册骰制生成随机骰池。
5. 插件读取已批准角色卡的最终修正。
6. 插件计算结果档位并持久化锁定回执。
7. 群内先显示检定结果。
8. 插件提示“后续内容正在生成中”。
9. 文字模型仅依据锁定回执续写。

示例：

```text
🎲【魅力检定】［常规］18 +1 → 19 / DC 9 · 大成功

【酒馆】已收到你的选择，后续内容正在生成中……

📖 【故事推进】
（模型根据已锁定结果续写）
```

### 风险与 DC

风险描述失败后果，DC 描述成功难度。DC 由世界包 `difficulty_policy` 决定，模型临时输出的 DC 不具有权威性。

典型风险 ID：

- `safe`：安全，不检定；
- `controlled`：可控；
- `dangerous`：危险；
- `desperate`：绝境；
- `lethal`：致命，必须提前显示玩家可见后果。

具体 DC 由当前世界决定。例如某世界可以声明“可控 9、危险 13、绝境 17、致命 21”，但这不是插件写死的全局数值。

### 优势与劣势

世界包可以声明：

- 优势：如 `2d20_keep_high`，掷两个 D20 取高；
- 劣势：如 `2d20_keep_low`，掷两个 D20 取低；
- 是否允许同类效果叠加；
- 优势与劣势是否互相抵消；
- 自然 1、自然 20 和成功差值规则。

同一个原因不应既提高 DC 又施加劣势，避免重复处罚。

### 灵感

```text
/酒馆 灵感
/酒馆 灵感 A 优势
/酒馆 灵感重投 A
```

- 第一条查询当前灵感余额和上限。
- “优势”在选择检定选项时消耗灵感，为本次骰池取得优势。
- “灵感重投”消耗灵感并重投完整骰池。
- 是否启用、初始值、最大值和允许用途由世界包决定。

### 属性中文显示

世界包可以使用 `faith`、`perception`、`charisma` 等英文稳定 ID 保存数据，但应同时提供“信仰”“感知”“魅力”等中文 `label`。插件在选项、检定回执、存档恢复和紧急替换中显示中文名称；只有找不到标签时才回退到稳定 ID。

## 八、集体投票

### 投票方式

```text
/酒馆 投票 A
```

- 只有当前集体决策列出的选项可投。
- 每位合格出场玩家拥有一票。
- 截止前重复投票会更新原选择，而不是增加票数。
- 系统显示各选项票数和已投人数。
- 形成多数后执行集体结果。
- 未形成有效多数时，队伍维持现状并重新获得个人选项。
- 第一轮无人过半时，世界规则可以开启前两项决选。
- 投票不消耗当前玩家的个人行动回合。

## 九、暂停、恢复、读档与回滚

### 正常暂停

```text
/酒馆 暂停
```

插件持久化现场、最后剧情、当前行动者、未完成选项、投票和计时剩余值。暂停期间默认不计时。

### 安全暂停

```text
/酒馆 安全暂停
```

任一当前出场玩家均可发起。故事、行动、投票与全部计时会立即冻结；玩家无需在群内说明原因。确认内容边界后，由主持人恢复。

### 正确恢复流程

```text
/酒馆 恢复
全员：/酒馆 准备
/酒馆 继续
```

- `恢复` 只进入恢复准备大厅，不推进剧情，也不恢复计时。
- 全员重新确认准备，避免离线玩家被直接拉回。
- `继续` 恢复暂停前的最后剧情、行动者、选项或投票，并继续剩余计时。
- 新故事尚未产生剧情时应使用 `/酒馆 开演`，不能使用 `/酒馆 继续`。

### 命名存档

```text
/酒馆 存档 <名称>
/酒馆 存档 <名称> 覆盖确认
/酒馆 存档列表
/酒馆 删档 <名称或存档ID>
```

- 只有运行中的故事可以创建新剧情存档。
- 同名存档不会直接覆盖，必须追加“覆盖确认”。
- 普通手动存档可以删除；保护存档和最终归档受更严格限制。

### 读档与回滚

```text
/酒馆 读档 <名称>
/酒馆 回滚
```

- `读档` 恢复指定命名存档。
- `回滚` 恢复最近一个自动保护点。
- 两种操作完成后都会自动暂停会话。
- 后续必须按“恢复 → 全员准备 → 继续”的流程重新开团。

### 回顾

```text
/酒馆 回顾
/酒馆 回顾 最近一轮
/酒馆 回顾 最近一章
/酒馆 回顾 我的经历
/酒馆 回顾 任务线索
/酒馆 回顾 NPC关系
/酒馆 回顾 请假摘要
```

回顾读取持久化剧情、状态和记忆，不等同于读档，也不会修改世界状态。

## 十、玩家进出、暂离、返场与代控

### 暂离

```text
/酒馆 暂离
```

角色暂时离开行动队列，但席位和角色历史仍保留。

### 返回队列

```text
/酒馆 返回队列
```

返回不会插队，通常从下一轮队尾生效。

### 正式退出

```text
/酒馆 退出
```

角色正式退场并释放席位，角色历史仍归档。主持人或秩序管理员可使用：

```text
/酒馆 退出 <角色名或代号>
```

让指定角色退场。

### 剧情返场

```text
/酒馆 申请返场
```

已退场角色可发起返场申请。系统依据世界的返场规则建立剧情条件，必要时进入集体投票；返场不是直接把角色无条件塞回当前场景。

### 授权代控

```text
/酒馆 授权代控 <真实用户ID> [时长]
/酒馆 撤销代控
```

时长示例：`30分钟`、`2小时`、`1天`。代控授权在以下情况立即失效：

- 到达有效期；
- 角色本人再次行动；
- 角色本人主动撤销；
- 角色退场；
- 角色或代控关系被封禁。

未获得本人授权的玩家不能替其他角色行动。

## 十一、倒计时与超时处理

### 设计原则

所有游玩倒计时在新副本中默认关闭。建卡码有效期、模型超时和数据库技术超时不等同于游玩倒计时。

只有主持人主动启用时间预设或副本倒计时开关后，准备、个人回合、投票和候补等倒计时才会实际运行。

### 七类倒计时

| 分类 | 作用 |
|---|---|
| 建卡码 | 建卡码绑定有效期 |
| 角色卡完成 | 玩家完成私聊建卡的时间 |
| 准备大厅 | 整个准备阶段的等待时间 |
| 准备确认 | 单个玩家确认准备的时间 |
| 行动回合 | 当前玩家选择行动的时间 |
| 集体投票 | 投票第一轮、第二轮及提醒 |
| 候补等待 | 候补角色自动退场前的等待时间 |

### 群内开关

```text
/酒馆 倒计时 状态
/酒馆 倒计时 总 开
/酒馆 倒计时 总 关
/酒馆 倒计时 回合 开
/酒馆 倒计时 回合 关
/酒馆 倒计时 投票 开
/酒馆 倒计时 投票 关
```

也可以使用紧凑写法，如 `/酒馆 倒计时 总关`。关闭总开关会冻结全部分类，但保留真实剩余时间，不执行超时处罚。

### 延长计时

```text
/酒馆 延时 <角色名、代号或准备阶段> <时长>
```

示例：

```text
/酒馆 延时 林照夜 30分钟
/酒馆 延时 准备阶段 2小时
```

### 超时策略

管理台可分别设置：

- 回合超时后跳过并累计，或继续保留行动权；
- 建卡超时后转候补、释放席位或仅提醒；
- 准备超时后转候补或仅提醒；
- 连续多少次行动超时后转候补，`-1` 表示永不自动转候补；
- 全员无互动多久后自动暂停；
- 暂停期间是否停止计时；
- 是否在群内公布超时提醒与处理结果。

## 十四、管理控制台

控制台包含“总览、世界与角色、群会话、审计记录、安全与设置”五个主区域。

### 总览

- 显示正在运行、准备、暂停和异常的副本指标。
- 查看当前正在发生的会话。
- 显示叙事引擎和数据库完整性。
- 提供开馆前检查清单。
- 展示常用群内指令参考。

### 世界与角色

- 新建、编辑、归档和查看世界模板。
- 导入、导出世界包 JSON。
- 对世界包执行结构体检和试运行。
- 编辑世界描述、规则、开场、初始状态、能力声明和版本字段。
- 单独管理角色卡模板，支持导入、导出、校验、表单预览、恢复默认和确认保存。
- 导入和管理常驻 NPC。
- 在同一世界内，NPC 导入按“NPC 名称”判断更新或新建；改名可能产生新记录。

- 以平台实例、群和副本检索故事。
- 添加群备注，便于识别不同群。
- 建立新副本或克隆已有副本。
- 查看会话状态、位置、章节、目标和正式里程碑。
- 查看完整阵容、角色资料、属性修正、卡片版本与私密字段。
- 添加或编辑玩家和副本 NPC。
- 调整回合顺序、指定行动者、处理投票和倒计时。
- 查看 AI 自动/DM 主持状态，开启或接管 DM、保存一次性指引、原文插入并恢复自动模式。
- 管理任务与剧情线账本、场景时钟、长期记忆和 NPC 关系。
- 创建、查看和恢复命名存档。
- 查看副本 Token 用量和滚动限额。
- 处理黑名单、角色卡修改申请和返场等工作流。

### 急救与诊断

- 识别事务停留在哪个阶段。
- 对未完成事务执行精确恢复，不盲目重跑整个回合。
- 查看独立安全文件和保护点。
- 导出脱敏故障报告。
- 诊断文件会哈希用户 ID，并排除密钥、私聊来源、私人字段和完整系统提示词。

### 审计记录

- 按会话筛选操作记录。
- 查看时间、动作、操作者、目标和详情。
- 审计日志按配置的保留天数清理。
- 权限变更、封禁、恢复、存档、世界导入和关键状态切换均可追踪。

### 安全与设置

- 管理真实管理员 ID、允许群和白名单策略。
- 配置未授权命令静默或明确拒绝。

- 设置审计保留、原始模型结构保存和调试日志。

## 十五、世界包、角色卡模板与 NPC

### 随包模板

| 文件 | 用途 |
|---|---|
| `templates/world-package.template.json` | 手动属性世界包的完整示例 |
| `templates/world-package-preset-stack.template.json` | 多来源属性自动结算示例 |
| `templates/npc-import.template.json` | 常驻 NPC 导入载荷示例 |
| `templates/template-manifest.json` | 插件、协议、角色卡和 NPC 模板兼容清单 |
| `templates/README.md` | 面向世界作者的逐项说明 |

### 世界包顶层核心字段

| 字段 | 作用 |
|---|---|
| `slug` | 世界唯一稳定标识；小写字母、数字、下划线、连字符，最多 64 字符 |
| `name` | 玩家可见世界名称 |
| `description` | 题材、规模和玩法简介 |
| `system_prompt` | 稳定世界规律、能力边界和叙事语气 |
| `opening_scene` | 第一次开演时的开场正文 |
| `rules` | 人数、角色卡、检定、内容边界、NPC、事件、进度和时间规则 |
| `initial_state` | 初始地点、时间、摘要、事实、物品和关系 |
| `world_schema_version` | 世界协议版本，当前接受 v2/v3/v4/v5 |
| `minimum_plugin_version` | 世界要求的最低插件版本 |
| `world_content_version` | 世界内容自身版本，不等于插件版本 |
| `template_metadata` | 模板与作者侧元信息，可在导入、编辑、保存和导出间保留 |
| `capabilities` | 声明世界实际启用的能力 |

### 角色卡字段类型与规则

角色卡模板支持文本、选择、预设选择、多选及数值派生流程。选择名单应放入结构化 `options` 或 `preset_sets`，不要把所有选项写进字段标题或系统提示。

预设字段可以使用：

- `preset_source` / `options_source`：引用预设集合；
- `page_size`：每页 1—10 项；
- `visible_when`：满足条件时才显示；
- `clear_on_change`：修改当前字段时清理指定后续字段；
- `must_differ_from`：不得与另一个字段选择相同值；
- `private`：群内不公开正文；
- `required`、`max_chars`：必填与长度限制。

体检会拒绝预设源不存在、必填字段没有有效选项、稳定 ID 重复、字段引用非法和条件循环依赖。

世界协议 v4 还支持：

- `preset_dimensions`：统一声明单选、多选、有序多选、条件、系统分配和作者固定维度；
- `knowledge_profiles`：为每个预设绑定结构化知识熟悉度、已知与未知事实；
- `content_profiles`：为预设增加禁止、淡出和叙事限制；
- `knowledge_boundary` / `content_boundary`：世界级硬边界，任何预设、玩家或 DM 都不能放宽；
- `requirements` / `conflicts`：由程序校验前置与互斥，不依赖模型自觉。

### 人数规则

世界可分别声明：

- 推荐最少人数；
- 推荐最多人数；
- 允许开演的最低人数；
- 数据库强制席位上限，范围 1—32。

推荐值仅用于展示；最低开演人数和最大席位属于强制规则。

### NPC 导入

NPC 文件顶层结构：

```json
{
  "world_slug": "目标世界稳定ID",
  "items": []
}
```

每个 NPC 至少需要名称；推荐补全：

- 身份、外貌、性格和公开背景；
- 阵营和所在地点；
- 确实知道的事实；
- 合理但可能错误的判断；
- 初始立场、合作条件和底线；
- 有明确来源的技能、资源和权限；
- 能力上限、知识盲区和资源限制；
- 隐藏动机、私人导演信息和秘密透露条件。

系统提示中的常驻 NPC 与运行时活动 NPC 会合并为精简投影，避免重复发送给模型。

### 机器骰制边界

- 世界包只声明骰制和确定性策略，不执行代码。
- `resolution.dice_system` 必须对应已经注册的骰制。
- 未找到骰制时拒绝开演或裁定，不会偷偷回退为 D20。
- 风险通过 `difficulty_policy` 映射 DC。
- `outcome_policy` 固定自然骰、成功差值和结果档位。
- 世界包是纯 JSON，不能包含 Python、JavaScript、模板表达式或网络请求。

## 十六、preset_stack 多预设属性自动结算

`v0.9.3` 新增正式的 `preset_stack` 接口，用于“基础属性 + 多个建卡预设来源 = 最终属性”的世界。

### 必要版本声明

```json
{
  "world_schema_version": 3,
  "minimum_plugin_version": "0.9.3",
  "rules": {
    "world_schema_version": 3
  }
}
```

使用该模式时，角色卡模板版本应为 4，`rules.character_card.stats.mode` 和 `rules.character_card.stat_generation.mode` 都应声明为 `preset_stack`。

### 示例配置

```json
{
  "stats": {
    "mode": "preset_stack",
    "attributes": [
      {"key": "body", "label": "体魄", "minimum": 2, "maximum": 5},
      {"key": "agility", "label": "灵巧", "minimum": 2, "maximum": 5}
    ],
    "modifier_table": {
      "2": -1,
      "3": 0,
      "4": 1,
      "5": 2
    }
  },
  "stat_generation": {
    "mode": "preset_stack",
    "base_stats": {"body": 2, "agility": 2},
    "bonus_sources": ["origin_region", "profession"],
    "bonus_source_rules": {
      "origin_region": {"expected_bonus_total": 1},
      "profession": {"expected_bonus_total": 1}
    },
    "expected_total": 6,
    "min_per_stat": 2,
    "max_per_stat": 4,
    "allow_manual_edit": false
  }
}
```

来源选项需要机器可读加成：

```json
{
  "id": "origin_jiangnan",
  "value": "江南",
  "label": "江南",
  "stat_bonus": {"agility": 1}
}
```

### 权威公式

```text
最终属性 = base_stats + 每个 bonus_sources 当前选项的 stat_bonus
```

系统始终从基础值重新计算，不在已保存属性上追加。因此反复修改同一来源、恢复建卡或重新审核不会造成加成叠加。

### 自动流程

1. 玩家依次选择全部来源字段。
2. 插件读取每个选项的稳定 ID 与 `stat_bonus`。
3. 从 `base_stats` 重新计算最终属性。
4. 验证最终总和与单项范围。
5. 生成并保存最终 `stats.raw` 和 `stats.modifiers`。
6. 保存 `stat_generation_snapshot`，记录基础值、来源字段、选项 ID、显示名和当时加成。
7. 向玩家显示最终属性及来源。
8. 跳过所有手动 `stat_<key>` 填写步骤，继续后续角色字段。

### 修改、恢复与审核

- 修改任一来源会清除旧派生结果并从基础值重算。
- 恢复未完成建卡时使用相同算法重建结果。
- 确认提交、审核展示和候选角色卡版本使用同一结算器。
- `allow_manual_edit=false` 时禁止通过 `/酒馆 重填数值` 篡改派生属性。
- 检定只读取已批准角色卡中持久化的最终修正，不在每次投骰时重新读取世界预设。

### 导入体检

体检会枚举全部合法组合，并拒绝：

- 基础属性没有覆盖全部属性键；
- 来源不存在、重复或不是单选字段；
- 任一来源选项缺少非空 `stat_bonus`；
- 加成引用未知属性；
- 加成使用布尔值、字符串或非整数；
- 来源总加成不符合 `bonus_source_rules`；
- 任一组合总和不等于 `expected_total`；
- 任一组合单项超出 `min_per_stat` / `max_per_stat`；
- 合法组合数超过 100000。

### 旧角色迁移

- 先根据旧角色现有预设选择复算。
- 若旧属性与复算结果一致，只补写来源快照。
- 若结果不同，标记为需要管理员确认。
- 未经确认，不静默覆盖旧角色的正式属性。

## 十七、上下文优化与生成速度

`v0.9.3` 不再把同一份完整世界包发送给所有模型任务，而是分别编译：

- 故事裁定上下文；
- 权威检定后的续写上下文；
- A—D 选项生成上下文；
- 选项结构修复上下文。

优化内容包括：

- 故事生成不携带角色卡建卡模板、职业预设、开场选项和完整事件池。
- 选项生成不携带数据库原始参与者行、绑定码、审核时间和重复角色档案。
- 当前行动者与下一行动者相同时使用引用，不重复发送完整角色卡。
- 常驻 NPC 与活动 NPC 不在不同层级重复发送。
- 选项修复只携带无效输出、校验错误和必要约束，不嵌套原始大提示。
- `safe + check` 直接由插件修正为安全免检，避免无意义的第二次模型调用。
- 默认最近回合数为 6、相关记忆数为 6、最大输出为 1400 Tokens、温度为 0.5。

若生成仍然较慢，优先检查：

1. 主模型本身响应速度和上下文窗口；
2. 是否频繁触发备用模型；
3. 世界 `system_prompt` 是否重复粘贴角色预设、事件池和 NPC 百科；
4. 最近回合数、记忆数是否被人工调得过高；
5. 是否开启原始模型结构保存和大量调试日志；
6. 模型是否经常输出非法 JSON，导致结构修复。

降低 `request_timeout_seconds` 只会更早失败，不会让模型真正生成得更快。

## 十八、数据安全、事务防重与诊断

### 普通群聊旁路

只有 `/酒馆...` 指令或满足“剧情前缀 + 空格 + 内容”的消息才会进入插件。普通群聊不调用模型、不写剧情、不改变回合。

### 权限与输入安全

- 管理命令校验管理员、主持人或秩序管理员权限。
- 群 ID、平台 ID 和世界标识执行格式校验。
- 玩家输入有字符上限并清理控制字符。
- 世界提示优先于玩家输入中的伪系统指令。
- 世界包为声明式 JSON，不能执行脚本。

### 事务防重

- 同一平台事件重复投递只消费一次。
- 同一回合操作通过会话锁串行处理。
- 检定在公开前写入权威回执。
- 模型超时或回执重放不会产生第二次骰点。
- 故事提交、回合推进、状态补丁和 Token 记录处于明确事务阶段。

### 自动保护

- 默认每 5 个回合创建自动快照，可在配置中调整或关闭。
- 暂停、读档、回滚和最终归档会保护关键状态。
- 完结和强制终止创建最终保护存档，之后只读保留角色、NPC、记忆、账本、时间线和存档。

### 完整备份

控制台可以导出完整 ZIP，包含目录库、群/副本数据、独立存档和兼容 JSON。导入时检查：

- 备份格式；
- Schema 8；
- 完整表集合；
- ZIP 路径安全；
- 文件校验和；
- 合并模式下的稳定 ID 冲突。

“安全合并”保留现有数据；“全部覆盖”会替换酒馆数据，应在确认备份来源和版本后使用。

### 删除与回收

`/酒馆 删除副本` 只能处理已关闭或已归档副本。角色、剧情、Token 流水、存档和独立数据库会一并移入回收目录；若文件移动失败，系统会明确报告数据库与文件状态。

## 二十、扩展接口

可信 Python 扩展可通过 `tavern.api` 和插件公开服务注册能力，而不是直接操作数据库。

### 可注册类型

- `dice_system`：骰制提供器；
- `check_resolver`：检定解析器；
- `world_validator`：世界附加校验器；
- `narrative_guard`：叙事质量守卫；
- `summary_provider`：摘要提供器；
- `admin_action`：受权限和审计约束的后台动作。

### 可观察生命周期事件

- `session_created`
- `character_approved`
- `turn_started`
- `option_selected`
- `check_completed`
- `vote_completed`
- `story_generated`
- `session_finished`

事件只在权威状态成功提交后触发。回调接收脱离 SQL 连接的字典副本；单个异步回调最多执行 2 秒，异常会被隔离，不会回滚主流程。

### v5 规则 API

- `resolve_action_intent(..., dry_run=True)`：用副本冻结快照验证并模拟通用行动，不写状态。
- `resolve_action_intent(..., dry_run=False, operation_id=...)`：以幂等事务提交操作；重复 ID 和相同输入返回原结果。
- `get_resolution_receipt(receipt_id, public_only=True)`：读取适合公开的结果与叙事约束；可信后台可请求完整读取值和状态差异。

世界包只能配置内置声明式操作，不能注册 Python 扩展或取得这组服务对象。

### 安全边界

- 扩展不能取得原始数据库连接。
- 扩展不能绕过权限、事务回执和审计。
- 写剧情、创建存档和读取回合必须调用公开 API。
- 同名扩展不能重复注册。
- 世界包不能携带扩展代码。
- 运行中世界契约继续冻结；改变属性、职业或数值模式时应新建副本。

## 二十二、常见问题与排查

### 1. 提示“酒馆尚未初始化”

原因：没有配置真实管理员 ID。

处理：进入控制台“安全与设置”，填写至少一个真实管理员 ID，保存后由该账号在目标群发送 `/酒馆 开启`。

### 2. 半角 `/酒馆` 没反应

某些 QQ 官方环境会拦截半角斜杠。改用：

```text
／酒馆 帮助
```

插件本身同时识别 `/`、`／`、`!`、`！`。

### 3. 机器人无法主动私聊玩家

这是平台限制。玩家应先主动打开机器人私聊，再发送：

```text
/酒馆 建卡 <验证码>
```

### 4. 导入 `preset_stack` 世界时报最低插件版本错误

确认：

1. 后台实际加载版本为 `0.9.3`；
2. 已安装最终修正版并重启 AstrBot；
3. 世界顶层声明 `"minimum_plugin_version": "0.9.3"`；
4. 世界顶层和 `rules` 中均声明协议 v3；
5. 浏览器强制刷新后重新导入。

### 5. 导入成功，但点击保存提示必须声明 `character_card.stat_generation`

这表示服务器或浏览器仍在使用早期 `v0.9.3` 管理台代码。最终修正版会优先保留世界包原始 `rules.character_card`，并在导入、编辑和保存链中保留顶层 `stat_generation`。

处理：覆盖安装最终修正版、重启 AstrBot、强制刷新管理台，再重新打开世界并保存。不要把 `stat_generation` 随意挪到 `stats` 内部。

### 6. 属性仍显示英文

内部英文属性 ID 属于正常存档协议，但玩家界面应显示中文标签。检查世界包 `stats.attributes` 是否为每个属性提供中文 `label`，并确认插件已升级到 v0.9.2 以上。找不到中文标签时系统才会使用稳定 ID 兜底。

### 7. 选完地区、身份和流派后仍要求手动填属性

检查：

- 世界协议是否为 v3；
- 最低插件版本是否为 0.9.3；
- `stats.mode` 是否为 `preset_stack`；
- `character_card.stat_generation.mode` 是否为 `preset_stack`；
- `bonus_sources` 是否引用真实单选字段 key；
- 所有来源选项是否都存在合法 `stat_bonus`；
- 是否正在继续一个使用旧冻结世界快照的副本。

旧副本不会因重新导入世界模板而自动切换规则；应新建或克隆副本。

### 8. 点击 A—D 后等待很久

依次检查主模型速度、备用回退、世界提示长度、最近回合数、记忆数和 JSON 修复日志。推荐先保持默认值：温度 0.5、最大输出 1400、最近 6 回合、6 条记忆。不要通过缩短超时时间“提速”，那只会更早失败。

### 9. 故事生成失败后会不会重复投骰

不会。检定回执在调用续写模型前已经锁定；模型失败、重试、恢复和结构修复都会复用原回执。

### 10. 暂停后恢复为什么不能直接继续

为了确认所有玩家仍在线，恢复分为两步：

```text
/酒馆 恢复
全员 /酒馆 准备
/酒馆 继续
```

暂停前的剧情、行动者、投票和选项不会丢失。

### 11. 新世界已更新，旧副本为什么没有变化

副本使用创建时冻结的世界快照，这是防止运行中规则漂移的保护机制。需要使用新版世界时，应基于新版世界新建副本，或从合适存档进行克隆与迁移评估。

### 12. NPC 导入后出现重复角色

当前导入规则在同一世界内按 NPC 名称判断更新或新建。若修改已有 NPC 名称，系统可能视为新角色。导入前应先核对目标世界的现有 NPC 名称。

### 13. 倒计时配置了却不运行

检查副本倒计时总开关以及对应分类开关。新副本默认全部关闭；分类开启但总开关关闭时，计时仍被冻结。

### 14. 富卡片不显示或指令看似没反应

平台可能没有对应模板权限。将富卡片模式改为文本或 `auto`，并检查日志中的平台错误。插件检测到富卡片不可用后会尝试回退文本。

### 15. 读档后为什么处于暂停状态

这是预期行为，避免读档后在无人确认的情况下立即恢复计时或推进。请执行“恢复 → 全员准备 → 继续”。
