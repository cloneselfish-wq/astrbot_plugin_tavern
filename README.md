# AI 酒馆

> 当前版本：`v0.7.0`  
> AI 主持的多人群聊跑团与互动叙事插件。

AI 酒馆面向 AstrBot 群聊运行。玩家在准备大厅加入副本、私聊建立角色卡，再进入有明确行动权、规则裁定和持久存档的多人故事。模型负责理解行动与生成叙事，插件负责校验权限、锁定骰点并原子保存关键状态。

普通群聊始终旁路：不调用酒馆模型、不写入酒馆时间线，也不进入长期记忆。

版本新增、调整与修复统一记录在 [CHANGELOG.md](CHANGELOG.md)。

## 兼容范围

- AstrBot `>= 4.26, < 5`
- OneBot v11 / NapCat（`aiocqhttp`）
- QQ 官方机器人 WebSocket / Webhook
- Python 标准库即可运行

## 主要功能

### 多人群聊跑团

- “准备大厅 → 私聊建卡 → 审核与准备 → 正式开演”的完整开团流程。
- 严格的玩家行动权、固定队列、候补、暂离、代控、返场与安全退场机制。
- 支持个人行动、集体投票、多人检定和完整轮次世界事件。

### 插件权威规则

- 支持 D20、优势／劣势、DC、风险等级和五档结果。
- 支持灵感、协助、伤势状态、场景时钟与剧情里程碑。
- 选项、裁定和骰点先由插件锁定并持久化，模型重试或切换不会重复投骰。

### 持久世界与叙事记忆

- 世界模板与故事副本分离，同一世界可在同一群或不同群多次开局。
- 副本独立保存玩家、角色、动态 NPC、长期记忆、剧情账本、时间线和运行状态。
- 内容边界与安全暂停由插件执行；AI 不替玩家决定内心、对白或感情。
- 每回合正文强制 100—300 字、选项不超过 50 字，并绑定下一位行动角色。

### 存档、归档与分支

- 每回合快速恢复点、自动检查点、手动存档和独立安全备份。
- 每个群、每轮故事副本均有独立目录和自包含数据库，降低单个副本损坏的影响范围。
- 完结与强制终止会永久只读归档；续作可从当前状态或指定存档克隆为新副本。
- 暂停与读档会恢复原剧情分支、活动选项、行动权和剩余时间，不重新生成开局选项。

### 管理台与模型可靠性

- 管理世界、角色卡模板、群备注、会话检索、阵容、权限、NPC、记忆、时钟和存档。
- 角色卡模板支持 JSON 导入、导出、校验、预览与恢复默认。
- 支持主模型、备用模型链、图片转述模型、失败熔断、配置回读和完整备份。
- 按群和副本统计模型 Token，并支持滚动时间窗限额与调用前原子预占。

## 核心流程

```text
/酒馆 开启 <副本>
        ↓
准备大厅：加入 → 私聊建卡 → 审核 → 准备
        ↓
/酒馆 开演
        ↓
/酒馆 选择 A / B / C / D
        ↓
插件锁定裁定与骰点 → 模型叙事 → 原子提交 → 下一位
        ↓
完整多人轮次结束 → 至多一次世界脉冲
```

`/酒馆 开启 <副本>`只进入准备大厅，不推进剧情。暂停、读档或回滚后，先发送 `/酒馆 恢复` 进入恢复准备大厅；全员重新准备完成后，再由主持人发送 `/酒馆 继续` 正式续演。

## 安装与升级

### WebUI 安装

1. 停止 AstrBot，并备份整个插件数据目录。
2. 在 AstrBot WebUI 的插件管理中上传发布 ZIP。
3. 重载插件或重启 AstrBot。
4. 打开“酒馆控制台”，检查世界、副本、角色模板、模型链和存档。

ZIP 内保留顶层目录 `astrbot_plugin_tavern`。

### 手动安装

将整个目录放到：

```text
AstrBot/data/plugins/astrbot_plugin_tavern
```

### 存档位置

全局目录库：

```text
AstrBot/data/plugin_data/astrbot_plugin_tavern/catalog.sqlite3
```

群与副本文件：

```text
AstrBot/data/plugin_data/astrbot_plugin_tavern/
└─ groups/
   └─ <平台>_g_<稳定群哈希>/
      ├─ group.json
      └─ stories/
         └─ <故事标识>_<创建时间>_i-<副本ID>/
            ├─ manifest.json
            ├─ instance.sqlite3
            ├─ saves/
            └─ backups/
```

升级前仍建议停机备份整个目录：

```text
AstrBot/data/plugin_data/astrbot_plugin_tavern/
```

若运行中复制目录库，必须同时保存 `.sqlite3`、`-wal` 和 `-shm`。更推荐停机复制或使用管理台完整 ZIP 导出。

旧版本升级、自动迁移、备份与回退方式见 [升级与存档说明](docs/UPGRADE_AND_SAVES.md)。

## 第一次开馆

1. 在插件配置中填写至少一个真实管理员用户 ID。
2. 选择主叙事模型；按需配置备用模型和图片转述模型。
3. 在目标群发送 `/酒馆 开启` 查看世界与副本；超过 5 个时发送 `/酒馆 开启 第2页` 翻页。
4. 发送 `/酒馆 开启 <副本标识>` 进入准备大厅。
5. 玩家发送 `/酒馆 加入` 取得一次性建卡码。
6. 玩家主动私聊 Bot：`/酒馆 建卡 <验证码>`。
7. 私聊中按提示填写角色资料和数值，预览后确认角色卡。
8. 主持人使用 `/酒馆 审核` 查看待审名单，再按序号审核。
9. 玩家发送 `/酒馆 准备`。
10. 主持人发送 `/酒馆 开演`。

QQ 官方机器人无法保证首次主动私聊成功，因此始终保留“玩家主动私聊＋一次性验证码”的可靠路径。

## 管理台

“酒馆控制台”可以管理：

- 世界、人数范围、独立角色卡模板、D20 规则、事件池和时间规则
- 群会话卡片、章节目标、正式里程碑、异常恢复状态
- 准备阵容、角色审核、当前行动者、权限与封禁
- 副本 NPC、认知边界、疑似重复与生命周期
- 长期记忆治理、剧情账本、场景时钟、时间线和存档
- 倒计时总开关／分类开关、强制准备、Token 用量与群／副本滚动限额
- 完结、强制终止、永久归档和从存档克隆分支
- 归档只读浏览、独立存档回收与已关闭／已归档故事副本删除
- 主模型、备用模型、模型链健康、配置修订和完整 ZIP 备份

时间规则优先级为“插件全局默认 → 世界模板覆盖 → 当前副本快照”。修改模板不会静默改变正在运行的副本。
